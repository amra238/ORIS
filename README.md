ИНСТРУКЦИЯ К СЕМЕСТРОВОЙ РАБОТЕ 1

Оригинал сайта по ссылке: https://www.coral.ru/kazan/goryashchie-tury/
Сервер запускается внутри MiniHttpServer(докер отсутствует). В проекте есть реализация ORM системы, шаблонизатора, а также тесты на шаблонизатор. 

структура проекта MiniHttpServer:
В папках abstracts и Attributes внутри папки Core хранятся интерфейсы с абстраутным классом и атрибуты соответственно. В папке handlers содержится два хендлера для обработки эндпоинтов и загрузки статических файлов из папки static, где хранится весь js, html и css код.  В папке Models хрянатся классы для сущностей из БД(наименовая полей в точности соответствуют полям в таблицах из БД). В папке Endpoints находится HomeControllerEndpoint, который отвечает за реализацию всех методов эндпоинтов таких как: подгрузка туров с учетом активных фильтров, авторизация, добавление турови и загрузка второй страницы. В папке Services есть класс для авторизации, а в папке Shared прочие вспомогательные классы в том числе сам класс HttpServer. Точка входа(Main) находится в файле program.

Функционал и работа сайта: 
после запуска сервера на главную страницу можно попасть по адресной строке localhost:1234 или localhost:1234/ или localhost:1234/static/..., после происходит загрузка туров, при неудачной загруке выйдет сообщение о ошибке. Над основным списком туров есть блок "Горячие туры", где будут отображаться все имеющиеся туры по горизонтали, их можно будет проматывать по циклу с помощью боковых кнопок и на них не распространяются фильтры! При введении информации в поля и фильтров и нажатии кнопки "поиск" на месте основного в основном списке будут отображатся все туры, удовлетворяющие настройкам фильтра или сообщение об отсутствии туров под филтры. На каждом из туров можно нажать кнопку "выбрать", после чего пользователя переведет на вторую страницу, где будет отоюражатся детальная информация о выбранном туре(Актуальная информация берется из БД таблицы Tour). 
На главной стрпнице в правом верхнем углу экрана юудет кнопка войти или зарегестрироваться, при нажатии откроется форма. При вводе нового email, имени и пароля создается новый пользователь и сессия под него (таблицы user и session в БД создаются автоматически при их отсутствии с помощью orm, права всех новых пользователей по умолчанию admin, это можно исправить в классе user или вручную прописать права user в БД, для каждого пользователя может существовать только одна уникальная сессия одновременно). При вводе существующего email, сервер будет проверять пароль и имя на коррекность на аутентификации. После регистрации нового пользователя или авторизации существующего, кнопка в верхнем углу сменит текст на "Привет, {ваше имя}!". При наличии у пользователя роли admin рядом с кнопкой поиск появляется кнопка административной панели(из-за новой кнопки, кнопка поиск смещается ниже). При нажатии на нее появятся поля формы для создания нового иура, при заполнении всех данных, создастся новый тур в БД и прогрузится. Кновка админки будет появлятся или пропадать  в зависимости от наличия роли admin или user
